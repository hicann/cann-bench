# 接入整网模型优化任务

先按 [README 的快速开始](../../README.md) 克隆 `skeleton` 分支、安装依赖、设置 `PYTHONPATH`，并在仓库根目录跑通分类模型示例。该示例用两个固定权重的仿射层演示 CPU 上的基线、整网输出等价与端到端测量。完成后，可复制 [分类模型任务包](../../tasks/example.model.classifier/) 接入自己的任务。

1. 修改 `task.yaml` 的 ID、版本和资产路径，将 `objective` 设为 `optimize`、`scope` 设为 `model`。把真实的任务契约、工作负载、答案示例及对应资产放入任务包，或用仓内清单引用固定版本的模型和权重。
2. 在契约中明确推理或训练、输出精度或模型质量门槛、初始化与状态重置、允许使用的库及可改文件。整网允许多算子组合或融合时，给这些方案使用相同的输入输出和验证边界。
3. 在资源配置中登记已验证的设备、最低卡数、显存、主机内存和互联拓扑。软件配置固定编译器、运行时、依赖和镜像。用例应覆盖已声明的 batch、动态 shape、状态和多卡场景。
4. 性能规则可参考 [耗时比规则](../../scoring/latency-ratio.v1.yaml)。另行定义计时从输入就绪到输出可用的边界，明确主机和设备同步、传输、通信、预热、状态复位与采样。先完成正确性校验，再在匹配的环境和负载下测基线与候选。
5. 在 [适配器目录](../../src/cannbench/adapters/) 接入团队评测器。适配器接收仓库根目录、任务、提交、报告目录和运行选项，返回 argv 列表。用 [Engine](../../src/cannbench/engine.py) 的适配器注册表接入，团队 CLI 可复用同一入口，参考 [CPU 示例适配器](../../src/cannbench/adapters/python_example.py)。
6. 运行 `python -m cannbench validate --schema` 检查任务和题集清单。用示例答案、输出错误的候选和无法导入的候选，分别检查正确性、计分资格及失败报告。CPU 示例适配器在候选加载失败时生成带 `candidate_import` 阶段的 `example_result.json`，团队评测器可沿用这一归因方式。在目标硬件验收后向 `suites/` 登记固定任务版本。提交工件和账号凭据需与可信基线、评分规则和评测环境分开管理。

如果只改变测量边界，保留相同公式并使用独立测量配置。公式、指标、用例聚合或失败处理变更时，发布新的评分规则版本，并同步更新任务引用。
