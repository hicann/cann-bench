# 任务包与题集

`tasks/<task-id>/task.yaml` 声明任务 ID、版本、目标、范围和状态。所有资产及配置路径相对于仓库根目录，任务目录名称与 ID 一致。示例使用 `example`，新增未验收赛题使用 `draft`。

| 部分 | 声明内容 |
|---|---|
| `objective`、`scope` | 开发目标与计算范围，例如 `optimize`、`model` |
| `assets` | 问题、输入输出和可改边界、用例、答案示例。按目标补充 oracle、starter、固定性能基线 |
| `resources` | 配置引用、已验证平台、最低资源与可选推荐资源。未验收值保留为空 |
| `evaluation` | 适配器、提交类型和固定版本的评分规则路径 |

某份文件可以承担多个角色，例如官方基线同时是起始实现与正确性参考。性能优化应声明这三个角色。生成题没有起始代码时可省略 starter。

共享评分规则定义指标、公式和失败处理，题目契约定义本题的阈值、基线和测量边界。题集用 ID 与版本引用任务。需要合成榜单总分时，题集应声明权重和聚合规则。示例题集分别报告每题结果。

发布前验证所有强制用例、答案示例、最低资源和适配器，并冻结任务、评分、基线及环境版本。已发布的题集需要固定素材来源提交。`validate --schema` 校验声明和引用，硬件实测由任务验收提供。
